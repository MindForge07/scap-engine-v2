# 跨领域本质案例采集机制设计（Essence Case Collection）

> 状态：**设计草案**（未实现） | 关联：`bisociation-design.md` §7（聚焦类比实验）
> 动机：聚焦类比实验证明「同本质经验跨域迁移」改变思考方向、深度 +14%，但 SCAP
> 当前经验库几乎全是工具坑（编码/脚本/环境），**缺少可跨域迁移的本质案例**。
> 本设计回答：什么样的经验值得记为可迁移案例？如何采集、如何存储、如何被召回？

## 1. 问题现状（2026-08-14 盘点）

XDXLC 原生经验 13 条分类：

| 类型 | 示例 | 可迁移性 |
|---|---|---|
| 工具坑（9 条） | GBK 编码、junction 递归删除、tsx loader | **低**：领域绑定（Windows/PS），迁移价值仅限同环境 |
| 工程原则（2 条） | 测试≠效果、文档滞后=失信 | **中**：跨项目适用，但非「机制」级 |
| 记忆架构洞察（2 条） | 检索悖论、聚焦类比结论 | **高**：跨领域本质案例的雏形 |

结论：当前库缺少「**机制级、跨领域、已验证**」的案例——这正是聚焦类比通道的燃料。

## 2. 判定标准：什么样的经验值得记为本质案例

三条硬门槛（**全部满足**才入库，对应记忆正确性门禁）：

1. **机制可分离（Mechanism-Extractable）**：能从具体情境中抽取出独立的
   **机制描述**——一句话能说清"它解决的是哪类本质问题、核心策略是什么"。
   例：水坝案例 → 机制 = "上游波动下保护有限下游容量：测输入、显式上限、
   先于上限行动、先丢低优先级"。工具坑（"PS 5.1 读 GBK"）**抽不出**机制 → 排除。
2. **跨域可迁移（Cross-Domain Transferable）**：机制描述**不包含领域专有名词**
   （无 Windows/PS/SQLite/Redis 等），仅用通用词汇表达，使另一领域的人能理解。
   例：水坝案例的机制描述全是通用词；"junction" 则领域绑定。
3. **已验证（Verified）**：机制在其原始领域**真实发生过并解决了问题**
   （来自真实经验/决策，非教科书、非推测）。验证方式：原经验有 situation→action→lesson
   完整链路 + 结果（fixed/success）。

不满足 1-2 条 → 普通经验（仍进 L1）；满足 1-2 但未验证 → 候选池（需补验证）；
全部满足 → 本质案例（进联想池，供聚焦类比召回）。

## 3. 存储模型：EssenceCase（SCAP 记录扩展）

在现有 Experience 之上增加**可迁移案例层**，通过 tagging + lesson 规范标记
（零 schema 变更，与 `learnings-to-scap.py` 的联想池一致）：

```
Experience (project=XDXLC, importance=4-5)
  situation   = 原始领域情境（保留细节，供追溯）
  action      = 原始领域解决动作
  lesson      = 【机制描述】（跨域通用版，无领域名词）+ 原始教训
  tags        = ["essence", "<mechanism-id>", "domain:<原始领域>"]
```

- `mechanism-id`：从预置机制词典（`scap-injection.ts` 的 `DEFAULT_MECHANISMS`）
  复用或扩展——保证**写入与召回用同一套机制词表**（闭环）
- `essence` 标签：L1 词法召回天然低相关（跨域）→ 默认休眠；聚焦类比通道
  （L1.5-v2）按机制匹配召回
- lesson 头部用固定前缀 `【机制】`，使注入器可用正则提取（与元模式同理）

## 4. 采集机制：两条通道

### 4.1 自动提炼（低频 LLM，写入时触发）

新经验写入时（`scap_record_experience` 调用层），若满足以下启发式之一，
触发一次**提炼**（低频路径，允许 LLM）：

- 经验来自**跨领域问题解决**（situation 含"设计/架构/方案/解决"等词）
- 或 importance ≥ 4 且 lesson 长度 > 阈值

提炼 prompt（零写入权限，只产出建议）：
```
这段经验能否抽取出跨领域可迁移的机制？若可以，用无领域名词的一句话
输出机制描述；若不能，输出 NONE。
```

结果 `NONE` → 普通经验；否则 → 写入第二条 `essence` 记录（或更新 tags），
经用户/审计确认后入库（**提炼结果不自动入库**——质量门禁，防幻觉机制）。

### 4.2 手工登记（低频人工，L2 工具）

MCP 新增工具 `scap_register_essence`（或复用 `scap_remember` + 约定 tag）：
用户/模型把一段**已验证的跨域经历**按「情境/动作/机制描述/领域」登记为案例。
这是种子来源——实验构造的水坝/地图/银行案例（已验证机制）可借此入库，
形成首批真实本质案例库。

## 5. 召回：L1.5-v2 聚焦类比通道（联动设计）

复用 `bisociation-design.md` 已验证的实验参数：

```
任务 T → matchMechanisms(T) → 机制 m
essence 池（tags 含 essence 且 lesson 含 m 的机制词）→ top-1
注入格式：
  ## 本质案例（聚焦类比）
  - [机制: m] 这段经验与当前问题本质相同，但发生在不同领域：
    <lesson 机制描述>。先分析它如何解决，再迁移其策略到你的设计。
```

- 注入方式 = 实验 B 组（带聚焦指令）——实验证明无提示效应（B≈C），
  但聚焦指令对**人类可读性**更好，保留
- 默认关闭（`assocLane: false`），复验确认深度增益可复现后再开

## 6. 验证方案

1. **机制抽取质量**：从现有 13 条经验跑提炼 prompt，统计可抽取率
   （预期：工具坑 0/9，原则 1/2，洞察 2/2——验证判定标准区分度）
2. **复验实验**（`analogy-exp.ps1 -Runs 5` 运行中）：确认深度 +14% 可复现、
   质量持平或更好、t3 过度聚焦风险是否重现
3. **端到端**：3 个 essence 案例入库 → 新任务触发召回 → 注入 → 对比无注入
